# Übergabe L6 – Urlaub, Abwesenheiten, Kalender/Planung, Freigaben

Branch `l6-planning-ui` (nicht gepusht). Backend nur gelesen (Vertrag v0.3.0, ADR-0005 „Fachregeln Etappe 3a“). Code/Tests englisch, UI deutsch (`src/lib/i18n/de-planning.ts`, in `de.ts` eingebunden).

## Routen und API-Aufrufe

| Route | Aufrufe |
| --- | --- |
| `/vacation` | GET `vacation/balance?year`, GET `vacation/settings` (404 = nicht eingerichtet), PUT `vacation/settings`, POST `vacation/snapshots`, POST `vacation/adjustments` |
| `/calendar?date=` | GET `calendar/holidays?year` (je berührtem Jahr), GET `absences`, GET `plan/days`, GET `time/days` (optional, Fehler ignoriert), GET `places`; Aktionen: POST/PUT/DELETE `absences`, PUT/DELETE `plan/days/{date}`, POST/DELETE `calendar/custom-days` |
| `/absences` | GET `absences` (Jahr), POST, PUT mit `If-Match: version`, DELETE; Filter Status/Art clientseitig |
| `/settings/sharing` | GET/POST `shares`, PATCH `shares/{id}` (Schalter), DELETE (Widerruf, zweistufig) |
| `/shared` | GET `shares/incoming`, GET `shares/incoming/{id}/view?from&to` (404 -> „widerrufen“) |

Alle Seiten: 404/501 beim ersten Laden -> „noch nicht verfügbar“. Navigation: Kalender, Urlaub, Abwesenheiten, Geteilt; Einstellungen -> Freigaben.
Anzeige: Dauer h:mm, Urlaub aus halben Tagen („12,5 Tage“, `src/lib/vacation/halfdays.ts`), Datum dd.MM.yyyy (ISO in der API).

## Mock-Verhalten (`mock/planning.ts`, `mock/holidays.ts`)

Zählung je Kalendertag: Arbeitstag des am Datum gültigen Modells (ohne Modell: Mo–Fr) und kein Feiertag (eingebaut für Region + eigene `holiday`) = 2 halbe Tage; `halfDayStart`/`halfDayEnd` -> 1; Eintagesabwesenheit mit einem Flag -> 1.
Saldo ohne Stichtag: Anspruch + Übertrag + Korrekturen − gebucht (approved/taken, einmal gezählt); mit Stichtag S im Jahr: S + Korrekturen ab S − gebucht ab S, Anspruch/Übertrag als 0 gemeldet. Geplant/beantragt separat (`availableAfterPlanned`).
Überlappung -> 409 `absence_overlap`; PUT ohne/mit falschem `If-Match` -> 400/412 `stale_version`; Freigabe-Widerruf -> 404 für Empfänger; unbekannter Empfänger 404 `recipient_not_found`; doppelte Freigabe 409 `share_exists`.
Demo: Admin hat Einstellungen (30 Tage/DE-ST), Urlaub genommen/genehmigt/geplant, Krankheit, Planung für zwei Wochen, Schulferien; zweites Konto `lena` (kein Login) teilt Plan + Urlaub (nicht Ist) mit dem Admin. `createMockFetch({ seedPlanning: false })` = unkonfiguriert.
Nicht im Mock: Abwesenheiten wirken (noch) nicht auf `time/days` (Tagesmarkierung, `targetOverrideSeconds`); Übertragsverfall wird nicht berechnet.

## Offene Vertragsfragen (Vertrag nicht geändert)

1. `GET vacation/settings` ohne gespeicherte Werte: 404 oder Standardwerte? UI behandelt 404 als „nicht eingerichtet“ und zeigt 30 Tage/DE-ST nur als Vorschlag; bei Standardwerten wäre „nicht eingerichtet“ nicht erkennbar.
2. `VacationBalance` mit Stichtag: Sind `entitlement/carryOver` dann 0 und `adjustment/booked` „ab Stichtag“? Die UI leitet den Stichtagsbestand als `available − adjustments + booked` ab; besser ein Feld `snapshotRemainingHalfDays`.
3. Übertragsverfall: ADR nennt „Vorschau“, es gibt aber kein Feld (z. B. `expiringCarryOverHalfDays`). UI zeigt nur Hinweistext aus den Einstellungen. Außerdem ist `carryOverHalfDays` global statt je Jahr.
4. Es gibt keine Listen für Stichtage/Korrekturen und kein Löschen/Ändern (Historie nicht sichtbar).
5. Überlappung: Blockieren `cancelled`/`rejected` andere Abwesenheiten? Mock: nein.
6. `countedHalfDays` für `rejected/cancelled/sick/other`: berechnet oder 0? UI zeigt „Zählt nicht“ bzw. „Betrifft … an Arbeitstagen“.
7. Freigabe: doppelte Freigabe (Upsert oder 409 `share_exists`?), Freigabe an sich selbst, Eintragsgrenzen. Sichtbarkeit von `vacation` in der Ansicht: nur approved/taken (Mock-Annahme) oder auch geplant? `actual`: nur Tage mit Arbeit?
8. Maximale Zeitraumlänge für `absences`/`plan/days`/`shares/.../view` (UI fragt bis zu 366 Tage ab; `time/days` begrenzt auf 93).
9. Kein Endpunkt zum Lesen eigener eigener Tage ohne Kalenderjahr-Abruf; `calendar/holidays` liefert eigene Einträge mit `id` (genutzt zum Löschen).
10. Nach `PUT absences` 412 gibt es kein `GET absences/{id}`; die UI lädt die Liste neu.
