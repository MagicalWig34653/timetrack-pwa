# Handoff V1 (PWA): Version und Build in der Hilfe

Stand: 18.10.2026. Branch `v1-version-info` (Worktree `timetrack-pwa-wt/v1`), nicht gemergt. Backend-Teil, Vertrag v0.19.0 und Entscheidungen: `docs/handoffs/V1.md` und ADR-0023 im Backend-Repo.

## Was gebaut ist
- Build-Metadaten: `scripts/build-info.ts` (`resolveBuildInfo`): Version aus `PWA_VERSION`, sonst package.json; Revision aus `PWA_REVISION`, sonst `git rev-parse HEAD`, sonst `unknown`; Datum aus `PWA_BUILD_DATE`, sonst Build-Zeit. `vite.config.ts` bettet sie per `define` ein (`__APP_VERSION__`, `__APP_REVISION__`, `__APP_BUILD_DATE__`) und schreibt `build/version.json` über einen Adapter-Wrapper um `adapter-static` (das Backend liefert die Datei als `pwa` in `GET /api/v1/system/info`).
- Hilfe-Dialog (`HelpDialog.svelte`, jetzt 36 rem breit und scrollbar) enthält `VersionInfo.svelte`: Karten „Oberfläche (PWA)“ und „Server (Backend)“ mit Version, Image-ID (Commit, 7 Zeichen monospace, Kopieren-Knopf für die volle SHA), Build-Datum; Backend zusätzlich API-Version, Datenbank, Migrationen (ausstehend?), Laufzeit, Replikat. Knopf „Angaben kopieren“ (eine Zeile für Fehlerberichte), Hinweis mit dem `docker service inspect`-Befehl für den Digest.
- Abweichende PWA-Revision (Server vs. geladen): Warnhinweis mit „Neu laden / Aktualisieren“ (Service Worker abmelden, Caches löschen, neu laden). Unbekannte Revisionen lösen nie den Hinweis aus.
- Ältere Server ohne Endpunkt: nur Oberflächen-Angaben plus Hinweis, kein Fehler.
- Logik in `src/lib/version/info.ts` (Unit-getestet); Texte `version.*` in `de-design.ts`; Mock `GET /system/info` (`mock/api.ts`, `pwaBuild` aus dem Dev-Server).
- Nebenbei (Auftrag des Leads): auf der Adminseite E-Mail ist der Verweis auf die Konfigurationsdoku ein externer Link (neuer Tab, `rel="noopener"`) auf die GitHub-Pages-Seite.
- Native Apps: nicht Teil des Pakets; Endpunkt in ADR-0023 dokumentiert.
