# Übergabe L9 – Export, Import, Dateispeicher, Anhänge

Branch `l9-export-import-storage-ui` (nicht gepusht). Backend nur gelesen (Vertrag v0.4.0, ADR-0006). Code/Tests englisch, UI deutsch (`src/lib/i18n/de-transfer.ts`), Dauern h:mm.

## Routen und API-Aufrufe

| Route | Aufrufe |
| --- | --- |
| `/export` | GET `export/time?from&to&format` (Blob, Dateiname aus Content-Disposition, Fallback `Arbeitszeit_<von>_<bis>.<fmt>`); Client prüft 366 Tage vorab |
| `/import` | POST `imports` (multipart), GET `imports/{id}/preview?sheet`, PUT `imports/{id}/mapping`, POST `imports/{id}/commit` (`ignoreErrors`), POST `imports/{id}/rollback`, DELETE `imports/{id}`, GET/POST `import-templates`, DELETE `import-templates/{id}` |
| `/settings/storage` | GET/PUT `admin/storage` (Admin; 403 -> Hinweis ohne Aufruf für Nicht-Admins) |
| Abwesenheitsformular (Bearbeiten) | GET/POST `absences/{id}/attachments`, DELETE `absences/{id}/attachments/{fileId}`, POST `files`, GET/DELETE `files/{id}` |

Navigation: Export, Import; Einstellungen -> Dateispeicher (nur Admin). 404/501 -> „noch nicht verfügbar“ (Anhänge/Vorlagen: Teilhinweis). Fehlerkörper werden in `ApiError.body` behalten (Konfliktliste).

## Mock-Verhalten (`mock/transfer.ts`, `mock/export-files.ts`, `src/lib/transfer/import-parse.ts`)

- Export: echtes CSV (BOM, `;`, Spalten tatsächlich/bewertet, Summenzeile, Formelschutz), XLSX/PDF nur Platzhalter mit korrektem Typ (PDF ist gültig, XLSX nicht öffnbar). >366 Tage -> 400 `range_too_large`.
- Import: nur CSV (xlsx-Upload -> 400 `import_unreadable`); Trennzeichen `;` `,` Tab, Anführungszeichen, BOM, Windows-1252; Datum dd.MM.yyyy / yyyy-MM-dd / Excel-Serial; Zeit HH:mm / Excel-Anteil / Dezimalstunden (7,7 = 7:42); Summenzeilen; Duplikate (Beginn+Ende+Art, auch gegen vorhandene Segmente); Überlappung -> Fehlerzeile; Formelzelle -> `formula_without_value`; Commit legt Segmente über den Zeitmock an (erneuter Import: nur Duplikate); Rücknahme 409 mit `conflicts` (Segmente mit Version != 1), sonst Segmente storniert. 5-MiB-Grenze 413, falscher Typ 415.
- Speicher: Regelvalidierung (aufsteigend, letzte ohne Limit), Secret nie in Antworten, 501 ohne `storageSecretKey`-Option, Admin-only. Dateien: Typ-Whitelist mit Inhaltsprüfung, Dateinamen-Bereinigung, Backend nach Regeln (nur Anzeige).

## Offene Vertragsfragen

1. Rücknahme-409: wo steht die Konfliktliste (`conflicts` auf oberster Ebene oder in `error`)? Die UI liest beides; der Vertrag nennt nur `ImportResult.conflicts`.
2. Ist `headerRow` 1-basiert (UI nimmt das an, 0 = keine)? Ebenso Zeilennummern in `errors[].row` (1-basiert, Tabellenzeile).
3. Wie wird Schule/Fahrt aus der Art-Spalte erkannt (UI-Hinweis nennt Arbeit/Fahrt/Schule)? Unbekannte Art im Mock: `missing_value`; kein Fehlercode `unknown_kind`.
4. Rücknahme ist nur direkt im Ergebnisschritt möglich; es gibt keine Importliste (`GET imports`) und kein Wiederfinden nach Verlassen der Seite.
5. Beim Entfernen eines Anhangs löscht die UI zusätzlich die Datei (DELETE `files/{id}`); gewünscht oder nur Verknüpfung lösen?
6. XLSX: mehrere Blätter/Blattnamen nur gegen echtes Backend prüfbar (Mock kennt `Tabelle1`).
7. `StorageSettingsInput.s3` ohne neues Secret: UI sendet `secretAccessKey` nicht; Server muss das alte behalten.
8. Anhangs-Upload bei Fehler beim Verknüpfen: UI löscht die verwaiste Datei (best effort).
