Stand: 23.10.2026. Branch `p12-stats-trash-week` (auf main 15d48bb), nicht gepusht, nicht gemergt. Keine neue Bibliothek (Diagramme sind eigene Inline-SVG-Komponenten), daher kein Eintrag in LIZENZEN.md nötig.

## 1. Wochensaldo unter der KW (Kalender)
- `src/lib/planning/week-balance.ts` (+ `week-balance-text.ts`): Differenz Ist minus Wochensoll aus `GET /time/days`. Abgeschlossene Woche: `+2:10 h` (grün, dezent) / `−3:05 h` (nur dann Warnfarbe Amber). Laufende/künftige Woche neutral: `noch 3:05 h offen`, bei Übererfüllung `+X h`. Kein Alarm, keine Rotfärbung.
- `WeekBalanceLabel.svelte`: Tooltip „… · Soll 38:30 h · Ist 36:25 h“, `aria-label` „Kalenderwoche N: …“. Anzeige in der Monats-/Wochen-KW-Spalte (Spalte 5,5 rem), in der Handy-Wochenliste und über dem Inspector (Wochenzeile der gewählten Tagesauswahl).
## 2. Statistik `/stats` (Kern, Navigation „Statistik“ unter Alltag)
- Zeiträume 4/12/26/52 Wochen, Dieses Jahr, eigener Zeitraum; Auflösung Tag/Woche/Monat; Schalter „Bewertete Zeiten (gerundet)“ (aus = Rohzeit ohne Rundung).
- Diagramme (eigene SVG-Komponente `components/stats/Chart.svelte`: Linie, Balken, gestapelt; Tooltip bei Hover/Fokus, Pfeiltasten, Tabellenalternative, aria-Label, hell/dunkel): Zeitkonto-Verlauf, Soll/Ist, Mehr-/Minderzeit, Verteilung nach Art, Abwesenheiten je Monat, Ø Beginn/Ende, Pausen; KPI-Karten; Leerzustand.
- Datenschicht: `src/lib/stats/source.ts` (`StatsSource`): `apiSource` nutzt `GET /time/statistics` (Vertrag 0.28.0; zusätzlich Monatsreihe für das Abwesenheitsdiagramm); Ø Beginn/Ende liefert der Server nicht und kommen best effort aus `daySource` (`time/days` + Segmente). Ältere Server ohne Endpunkt: komplett `daySource`. Reine Aggregation in `aggregate.ts` (getestet). Ein Statistik-Endpunkt aus Backend W3 lässt sich über `useStatsSource()` austauschen, ohne Seite/Diagramme zu ändern.
- Zukünftige Tage zählen weder zu Soll noch Saldo.
## 3. Stornierte Einträge `/time/cancelled` (Link auf `/time`)
- Filter Von/Bis (Standard 365 Tage) und Art; Mehrfachauswahl; Wiederherstellen; Endgültig löschen einzeln und markiert; „Alle stornierten endgültig löschen“ mit Zählvorschau (dryRun) und getipptem Wort `LÖSCHEN`.
- **Endpunkte (Vertrag 0.28.0, Backend W3, Handoff `W3-cancelled-statistics.md`):** `GET /time/segments/cancelled` (Seiten à 200 werden vollständig geladen, Filter Zeitraum/Art clientseitig), `POST /time/segments/{id}/restore`, `DELETE /time/segments/{id}?permanent=true`, `DELETE /time/segments/cancelled?ids|from|to|all&dryRun` (Vorschau mit Anzahl Abschnitte/Korrekturen; 409 `segment_not_cancelled` lässt die ganze Anfrage scheitern). Fehlende Endpunkte älterer Server werden erkannt (Probe per dryRun; 400/404/405/501) und die Löschaktionen mit Hinweis ausgeblendet.
- Stornierte Abwesenheiten: nur Hinweis auf `/absences` (Status „Storniert“).
- Mock: alle Endpunkte inkl. `/time/statistics`, Test-Hook `POST /api/v1/mock/trash {purge,restore}` simuliert älteren Server.
## 4. /week
- Letzte Woche je Tab in `sessionStorage` (`timetrack.week.last`, try/catch); `?week` bleibt maßgeblich; ohne Parameter wird die gemerkte Woche per `goto(replace)` in die URL übernommen.
- Abwesenheiten (geplant, beantragt, genehmigt, genommen): Chip auf der Tageskarte, Panel „Abwesenheiten in dieser Woche“ mit zusammengefassten Zeiträumen; Warnung „noch nicht beantragt“ (geplant) und „beantragt, noch nicht genehmigt“; Links „Urlaub planen“ (`/vacation/planner`) und „Urlaub beantragen“ (`/absences`). Tageskarten-aria-label nennt die Warnung.
