# Handoff P8 (PWA): Urlaubsantrag-Vorlage auf den echten B7-Endpunkten

Stand: 19.10.2026. PWA-Branch `p8-vacation-form-b7` (auf main 0bc09bc, Vertrag 0.25.0), Backend-Branch `p8-licenses` (nur `docs/LIZENZEN.md`). Nicht gepusht, nicht gemergt. Gegenstück: Backend-Handoff B7, ADR-0026.

## Was sich geaendert hat
- `src/lib/vacation-form/form-template-store.ts`: Der Server ist die einzige Quelle der Wahrheit. Der stille IndexedDB-Rückfall bei 404/501 ist entfernt (ein 404 ist jetzt ein echtes Ergebnis, `module_disabled` bleibt ein Fehler). IndexedDB ist nur noch Cache je Konto-ID: nach `load`, `saveFile`, `saveMapping`, `remove` aktualisiert; gelesen wird er nur bei Transportfehler (`ApiError` Status 0). Dann `storage === 'offline'`, Schreiben schlägt mit `network_error` fehl (kein stilles Auseinanderlaufen). Ohne Cache bleibt es beim Netzwerkfehler. Cachefehler (IndexedDB gesperrt) brechen den Serverweg nie. Hat der Server keine Vorlage, wird der Cache gelöscht; schlägt der Mapping-PUT nach erfolgreichem Datei-PUT fehl, wird der veraltete Cache verworfen.
- Seite `/settings/vacation-form`: Abzeichen „Gespeichert in deinem Konto“ oder „Server nicht erreichbar: Kopie aus diesem Browser …“. Deutsche Meldungen: 413 `mapping_too_large` („Die Zuordnung ist zu groß …“), 413 `file_too_large` („größer als 5 MB“), 415 `unsupported_type` („keine PDF-Datei“), 409 `no_template` („Der Server hat keine Vorlage für dein Konto …“). `error.mapping_too_large` zusätzlich global in i18n.
- API-Typ `VacationRequestFormInfo` entspricht dem Schema `VacationRequestForm` (alle fünf Felder, nullable; `mapping` als Objekt).
- Mock (`mock/vacation-form.ts`, `MockRequest.contentType`): Reihenfolge wie der Server (falscher Content-Type 415, leer 400, zu groß 413, fehlende Magic Number 400), Mapping > 64 KB (in Bytes) 413 `mapping_too_large`, 409 `no_template`.
- Lizenzen: Backend `docs/LIZENZEN.md`, neuer Abschnitt „Laufzeit-Abhängigkeiten der PWA“ (pdf-lib MIT, unmaintained, Risiko und Ersatz `@cantoo/pdf-lib` benannt, transitive Pakete; pdfjs-dist Apache-2.0, NOTICE-Pflicht, Datenverzeichnisse prüfen) und Release-Checkliste. PWA-README verweist darauf.

## Offene Fragen
1. Der Cache bleibt beim Abmelden im Browser (je Konto-ID); Löschen beim Abmelden wäre eine Option (aus P6 unverändert).
2. Datei-PUT und Mapping-PUT sind zwei Aufrufe (nicht atomar); der Server behält beim Datei-Ersetzen die alte Zuordnung, die PWA setzt sie unmittelbar danach zurück.
3. Offline sind Schreibvorgänge bewusst gesperrt; Offline-Schreiben mit späterem Abgleich wäre ein eigenes Paket.
4. `pdfjs-dist`-Datenverzeichnisse (Schriften, cmaps) vor dem Release auf Auslieferung und Lizenz prüfen.
