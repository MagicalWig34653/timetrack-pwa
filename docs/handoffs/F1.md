# Handoff F1 – Favicon und App-Icons im Design der nativen App

Branch `f1-icons`. Problem: `/favicon.ico` fiel auf die SPA-HTML zurück, `src/app.html` kannte nur das apple-touch-icon; die PWA-Icons (Uhr mit Fortschrittsbalken) passten nicht zum nativen App-Icon.

## Umgesetzt
- **Quellen**: `static/icons/icon.svg` (512 px, dunkelblaues Rundquadrat mit Verlauf #1F2A4D → #0A0F22, geschlossener Ring #5E93FC → #2563EB, weißer L-Zeiger; geometrisch aus den Ebenen `Icons/source/*.svg` der Apple-App auf 512 skaliert) und `static/favicon.svg` (64 px, für kleine Größen: dickerer Ring, flache Farben, dunkles Rundquadrat, daher auf hellen und dunklen Tabs lesbar).
- **Raster** (`npm run icons` → `scripts/generate-icons.mjs`, Chromium-Screenshot mit Transparenz): `icons/icon-192.png`, `icon-512.png`, `icon-mask.png` (randlos; Inhalt liegt ohnehin innerhalb der 80-%-Sicherheitszone), `apple-180.png` (randlos, iOS rundet selbst), `favicon-32.png`, `favicon.ico` (16/32/48, PNG-komprimierte Einträge, Container im Skript selbst gebaut, nur Node).
- **`src/app.html`**: Links auf `/favicon.svg`, `/favicon-32.png`, `/favicon.ico` (48x48) vor dem apple-touch-icon. Manifest unverändert.
- **Test**: `e2e-pwa/pwa.spec.ts` prüft, dass die Favicons/apple-touch-icon mit Status 200 und Bild-Content-Type ausgeliefert und im `<head>` verlinkt sind. `scripts/serve-build.mjs` kennt jetzt `.ico` (`image/x-icon`).

## Hinweis Backend
`PWAStaticMiddleware` liefert vorhandene Dateien aus dem static-Ordner vor dem SPA-Fallback aus; `favicon.ico` liegt jetzt im Build. Content-Type für `.ico` ist dort nicht geprüft (Vapor-Standardzuordnung); bei Bedarf in der Backend-Middleware kontrollieren.
