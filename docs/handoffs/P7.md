# Handoff P7 (PWA): Anhangzahl und Anhangfilter vom Server (Vertrag 0.24.0)

Stand: 19.10.2026. Branch `p7-attachment-count` (auf PWA-main mit P6), nicht gemergt. Backend B6 (Vertrag 0.24.0).

## Umgesetzt
- `Absence.attachmentCount?: number` (optional typisiert, damit ältere Server tolerierbar bleiben).
- `/absences`: Zähler und Anhangfilter (mit/ohne) nutzen `attachmentCount` aus der Liste (`countsFromList` in `absence-list.ts`); keine `GET /absences/{id}/attachments` mehr beim Laden. Fehlt das Feld bei mindestens einem Eintrag, läuft der alte Rückfall (höchstens vier parallele Einzelabrufe, nur für fehlende Einträge). Die Zahl wird weiter live angepasst, wenn im aufgeklappten Bereich Anhänge hinzukommen oder entfallen.
- Der Filter „mit/ohne Anhang“ wird clientseitig aus den gelieferten Zahlen berechnet, weil die Seite Zähler je Filteroption braucht und die Liste ohnehin ein ganzes Jahr lädt. `api.listAbsences(from, to, { hasAttachment })` sendet den Serverfilter `hasAttachment=true|false` und ist getestet, wird aber von der Seite nicht verwendet (offene Frage 1).
- Mock auf 0.24.0: `attachmentCount` in Liste, Einzelabruf, Anlage, Update (zählt nur vorhandene, eigene Anhänge), `?hasAttachment=` (anderer Wert 400 `bad_request`), `GET /files/{id}?disposition=inline` (Whitelist png/jpeg/gif/webp/pdf/plain; `inline`, `nosniff`, `Content-Security-Policy: sandbox; default-src 'none'`; sonst `attachment`).
- Vorschau-Dialog unverändert (Blob). „In neuem Tab öffnen“ bleibt bei der Blob-URL: die CSP `sandbox` des Servers wurde im echten Browser-PDF-Viewer nicht geprüft (Headless hat keinen), daher kein Wechsel auf die Inline-URL.
